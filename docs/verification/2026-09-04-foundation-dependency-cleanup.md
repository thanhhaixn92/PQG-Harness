# Foundation Dependency Cleanup — 2026-09-04

## Scope

This follow-up stays inside Foundation Core. It does not upgrade the DeepSeek Harness `0.1.0-rc.6` wave, does not use `npm audit fix --force`, does not change runtime/product behavior, and does not start a business module.

The goal is to remove avoidable dependency-audit exposure without opening a coordinated DSH/OpenTelemetry migration.

## Baseline audit

A read-only audit on the post-WP7 Foundation source reported:

```text
14 vulnerabilities
11 moderate
3 high
0 critical
```

The findings split into two groups:

1. `fast-uri@3.1.5` (high) and `qs@6.15.3` (moderate), both transitive and fixable inside compatible ranges.
2. Twelve findings in a root-level direct OpenTelemetry package wave (`1.30.x` / `0.55.x`), including two high findings in the Jaeger/trace-node chain.

A source-usage probe found no PQG-owned import of `@opentelemetry/*`, no `JaegerPropagator`, no `OTEL_PROPAGATORS`, and no explicit global propagator registration. The pinned DSH rc.6 packages carry their own nested telemetry dependencies, so the reviewed root OpenTelemetry set was redundant for PQG-owned source.

## Remediation

The 17 unused root `@opentelemetry/*` direct dependencies were removed from `package.json`.

The lockfile was regenerated by npm, not hand-edited:

```text
npm install --package-lock-only --ignore-scripts
npm update fast-uri qs --package-lock-only --ignore-scripts
```

No `--force` and no DSH package upgrade were used. The refreshed dependency tree dropped from 611 installed/audited packages to 563 and removed 764 lockfile lines associated with the redundant root telemetry wave and superseded transitive resolutions.

The lock refresh itself reported:

```text
found 0 vulnerabilities
```

The temporary write-enabled lock-refresh workflow was then removed before final verification.

## Interpretation

`npm audit = 0` is a point-in-time result for the current lockfile and npm advisory database. It is not a claim that the entire supply chain is vulnerability-free or that future advisories cannot affect the same versions.

The DSH rc.6 compatibility wave remains intentionally frozen. Future DSH/telemetry changes still require isolated compatibility review, full source quality, controlled Preview smoke, observability verification, and rollback evidence.

Foundation Freeze remains blocked by the independent EdgeOne live gates and missing GitHub required-quality enforcement recorded in `docs/release/RELEASE_CHECKLIST.md`.
